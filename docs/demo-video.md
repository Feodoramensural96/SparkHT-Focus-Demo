# 五分钟 Demo 录制与成片

## 自动草稿

脚本从一轮真实会话的 `session.json`、`events.jsonl`、`report.json` 和机器人抓拍生成带本地 Qwen3-TTS 旁白的 MP4。它不会创建或修改指标，也不会把运行图片加入 Git。

```bash
.venv/bin/python scripts/render_demo_video.py \
  runtime/focus/fs_20260722_100300_12ac \
  --output runtime/focus-demo-draft.mp4
```

服务未启动时可先用 `--mute` 检查画面和时长。最终视频必须小于 5 分钟；使用 `ffprobe runtime/focus-demo-draft.mp4` 复核时长、分辨率和音轨。

## 需要人工补录的镜头

自动草稿覆盖架构、真实抓拍序列、最终统计、快慢抢占证据、性能和限制，但不能替代实体机器人正面镜头。用 Win11 主力机录制以下素材：

1. 15 秒横屏固定镜头：机器人、摄像头和 DGX Spark 同框。
2. 靠近机器人说“开始专注”，保留完整回答。
3. Step3 分析期间说“现在统计到哪了”，同时录到机器人和仪表盘。
4. 说“停止专注”，保留最终播报和仪表盘结果。
5. 将片头约 20 秒替换为实体镜头；真实运行画面不要重演成伪实时数据。

录屏访问 `http://<Spark-IP>:8780/`。电脑同时连接 Orulink Wi-Fi 和有线网络时，固定使用同一个地址，不在录制中切换；若 Windows Anaconda 启动了临时服务，需要为实际 Python 可执行文件添加专用入站规则，而不是关闭整个防火墙。

## 最终检查

- 视频不超过 5 分钟，1920×1080、H.264、AAC。
- 明确说相机 P95 当前未过线，并展示真实数值。
- 杯子只称为疑似移动，不声称确认饮水。
- 不展示配对码、绝对个人目录、完整对话日志或可识别的屏幕小字。
- 仪表盘数字与选定会话的 `report.json` 一致。
